## 1. 今回いちばん大きいもの — 効いていない機能が3つあった

社長が実機を触って挙げた指摘 7 件を調べた結果。**3 件は「無い」ではなく「効いていない」だった。**

### 1.1 パーツ提案の車種フィルターが、1件も除外していなかった

```
 適合車種を宣言しているのに1つも当たらない
   → getCompatibilityFor が defaultCompatibility（たいてい compatible）を返す
   → PartRecommendationService は incompatible の行だけを飛ばす
   → 飛ばす対象が1件も出ない
```

**スバル専用のパーツがプリウスの提案に並ぶ**状態だった。
機能は実装されていて、テストも通っていた。

**加えて、ID の書き方が実装と食い違っていた。**
サービスは車両を `toyota` / `toyota_prius` に変換して照合するが、
単体テストは `prius` を使っており、**サービスが一度も出さない形式を検証していた。**

### 1.2 空表示から先に進めない画面が 7 つあった

車両詳細のドライブタブは「ドライブログがありません」と出すだけで、記録する導線が無かった。
実装にはこう書いてあった。

```dart
// The drive-only tab has its own recording flow, so no CTA there.
```

別画面に導線はある。**だがこの画面から行けることの保証ではない。**

### 1.3 使えないボタンが、理由を言わずに薄くなっていた

PDF出力と整備履歴検索は、整備記録が 0 件だと `onPressed: null` になり無効色で描かれていた。
**無効にすること自体が唯一の説明**で、「まだ使えない」と「壊れている」を区別できない。

## 3. 品質状況 — テストが欠陥を守っていた

**今回いちばん重い発見。** 直した 3 件のうち **3 件とも、既存テストが
「いま欠陥と判断した挙動」を固定していた。**

```
 空状態の説明文を表示する            助言の文言を固定していた
 記録0件のときPDFボタンは無効        欠陥そのものを固定していた
 returns default for different maker 車種フィルターを無効にする側を固定していた
```

**テストが通っていることは、仕様が正しいことの保証ではない。**
3,988件という数字は、この観点では品質を意味しない。

### 追加した検査（以降 CI で落ちる）

| 検査 | 何を見るか |
|---|---|
| `test/ux/dead_end_test.dart` | `AppEmptyState` を全数走査し、次の一手が**必ず**出るか |
| `test/ux/layout_overflow_test.dart` | 4サイズ × 実際の文面で、はみ出さないか（40件） |
| `test/golden/ux_golden_test.dart` | 見え方を画像で残す（目視用・9枚） |
| `test/models/part_compatibility_filter_test.dart` | 車種で除外できているか |

### ゴールデンテストは、文字を検証していなかった

既存のゴールデン17枚を実際に開いたところ、**日本語もアイコンも全部 □（豆腐）**だった。
`docs/TEST_SCREENSHOT_REPORT.md` はこれを「スクリーンショット」として載せているが、
**検証できていたのは配置と色だけ**である。

`test/golden/font_loader.dart` を追加して直したが、
**`fontWeight: w500`（ボタン）だけは読めない**（macOS の日本語は `.ttc` でしか
手に入らず、`FontLoader` が2面目以降を読まない）。限界として註に明記した。

## 4. 現状の課題

### 🔴 課題1: iOS ビルドが通らない — 実機テストとストア申請が着手不能

```
 pod install   540秒（成功）
 Xcode build   703秒 → ** BUILD FAILED **
```

**ログに出ているのは警告だけで、失敗の原因が surface されていない。**
`HUMAN_TASKS.md` の **P1-9（実機テスト・未実施）** と **P3（ストア申請）** は、
ビルドが通らないと着手できない。

**7月レポートの「開発環境に Flutter SDK が無い」は解消した**（SDK 3.44.2 が入り、
テストもビルドも回る）が、iOS だけ別の理由で止まっている。

### 🔴 課題2: 未マージPRが 18 → 28 に増えた

7月に「最大のボトルネック」と書いたものが、**改善せず悪化している。**

```
 #149  今回の修正（空表示・チップ・車種フィルター）
 #148  事業フォーカス戦略
 #145  日本語OCR修正＋カタログ外入力
 #144  今週末の人間タスク実施プラン
 #142  オンボーディング文言の修正
 …他23本
```

**作ったものが main に入らないので、実機で確かめられない。**
実機で確かめられないので、今回のような「効いていない機能」が見つからない。

### 🟠 課題3: ペルソナテストが「空の状態」を一度も通っていない

指摘 7 件のうち **3 件は Persona A〜I のどのシナリオでも踏めない場所**だった。
既存シナリオは**中身が入った状態から始まる**ため、空の状態を通らない。

`Persona J（登録した直後の人）` を追加した（`PERSONA_SCENARIO_GUIDE.md`）。
空表示 10 画面を順に踏み、押せないボタンを全部押す。
**このペルソナにはシードデータを作らない**（空であることが条件のため）。

### 🟠 課題4: C2Cパーツ市場が凍結中で、検証もできなかった

`FeatureFlag.c2cPartsMarketplace: false` のため、パーツ一覧・マイ出品が出ない。
実装は完了している（`HUMAN_TASKS.md` P2-15）。

検証用のシード（`scripts/seed_parts.js`・300件・すべて架空商品名）を作り、
**起動時オプトイン**で開けるようにした。**既定は変えていない**
（凍結は製品判断で、テストも固定しているため）。

```bash
flutter run --dart-define=ENABLE_C2C_PARTS=true
```

### 🟡 課題5: 死んだコードと、未確定の表示

- **`TireInfoCard` はどこからも呼ばれていない**（呼び出し 0 件）。削除か組み込みか未定
- **タブレット幅で空表示が中央に間延びする。** 上限幅を設けるかは未判断

## 7. まとめ

**7月の課題（未マージPRの滞留・人間タスク未完）は、1つも解消していない。**
未マージPRは 18 → 28 に増え、iOS ビルドという新しい壁が加わった。

一方で、実機を触って**「効いていない機能」が3つ見つかった**ことは前進である。
**テストが通っていることは、仕様が正しいことの保証ではない**と分かったので、
同じ形を機械で拾う検査を 4 本入れた。

**次に効くのは、作ることではなく、作ったものを main に入れて実機で触ることである。**
