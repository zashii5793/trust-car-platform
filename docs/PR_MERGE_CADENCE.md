# PRマージ運用ルール（滞留と重複の再発防止）

**作成日**: 2026-07-13
**背景**: CI GREEN のPRが20件超滞留し、実装済みの価値が本番へ届かない状態が常態化（`docs/OPEN_PR_TRIAGE_2026-07-13.md`）。同種修正（CI・Haversine・#63）が別セッションで**重複実装**される問題も発生。これを仕組みで防ぐ。

---

## 根本原因

1. **マージの定期リズムが無い** — 夜間に毎晩PRが増え、人間のマージが不定期。
2. **ブランチが古いmainから離れる** — 放置でbase差が開き rebase コスト増 → さらに滞留、の悪循環。
3. **重複実装** — 夜間エージェントが着手前に既存オープンPRを確認しないため、同じ修正が別ブランチで再実装される。

---

## ルール1: 週次マージデー（人間・15〜30分）

**毎週きまった曜日**（例: 月曜朝）に、滞留PRをまとめて処理する。手順:

1. [ ] `docs/OPEN_PR_TRIAGE_*.md` の最新版（無ければ後述の自動生成）を開く
2. [ ] **依存チェーンを先頭に**マージ（例: #74→#75→#76）
3. [ ] **重複PRを先にクローズ**（同じ修正が複数あれば最新1本だけ採用）
4. [ ] 古いbaseのPRは GitHub「Update branch」→ CI GREEN 確認 → マージ
5. [ ] マージした Issue を close、関連ドラフトを整理

> 目安: **オープンPRを常に10本以下**に保つ。超えたらマージデーの頻度を上げる。

---

## ルール2: マージ後の後片付け（都度）

PRをマージしたら、その場で:

- [ ] 同じ機能を再実装している**重複ドラフトをクローズ**
- [ ] 未マージの関連ブランチを**最新mainへrebase**（base差を溜めない）

---

## ルール3: 夜間エージェントの着手前チェック（自動化・重複防止）

夜間セッションが**新しいPRを作る前に**、必ず既存オープンPRとの重複を確認する。CLAUDE.md へ以下を追記することを推奨:

```md
## 夜間開発の着手前チェック（必須）

新しいブランチ／PRを作る前に:
1. オープンPR一覧を確認し、着手予定の変更と重複がないか調べる
   （同じファイル・同じIssue・同じ修正種別か）
2. 重複があれば **新規PRを作らず**、既存PRをrebase／拡張する
3. どうしても新規にする場合は、PR本文に「なぜ既存PRと別にするか」を明記
4. 分岐は必ず**最新の main から**（古いブランチから切らない）
```

---

## ルール4: トリアージの半自動生成（任意・効率化）

`docs/OPEN_PR_TRIAGE_*.md` を手で作り直す代わりに、以下を定期実行して素材を得る:

```bash
# オープンPRを base/更新日つきで一覧（GitHub MCP または gh CLI）
gh pr list --state open --json number,title,baseRefName,isDraft,updatedAt,labels \
  --template '{{range .}}#{{.number}} {{.title}} (base:{{.baseRefName}} draft:{{.isDraft}}){{"\n"}}{{end}}'

# 各PRが最新mainから何コミット遅れているか（rebase要否の判定）
for pr in $(gh pr list --state open --json number -q '.[].number'); do
  echo "PR #$pr: $(gh pr view $pr --json commits -q '.commits | length') commits"
done
```

将来的には `/pr-triage` スラッシュコマンド（skill）化し、
「重複検出・依存推定・推奨マージ順」までを自動下書きするのが理想。

---

## 運用の成功指標

| 指標 | 目標 |
|------|------|
| 常時オープンPR数 | **≤ 10本** |
| PR作成〜マージのリードタイム | **≤ 7日** |
| 重複実装で無駄になったPR | **月0件** |
| priority:high Issue の滞留 | **0件**（実装済みなら1週内にマージ） |

---

_この運用は「開発速度」ではなく「反映速度」を上げるためのもの。作る量ではなく、届く量を最大化する。_
