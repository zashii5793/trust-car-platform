## 補足: なぜ滞留するか（構造的要因）

- 夜間自律開発で毎晩PRが1〜3本増える一方、**人間のレビュー/マージが追いつかない**。
- ブランチが**古い main から分岐したまま**放置され、後続PRとの base 差が開く → rebase コスト増 → さらに滞留、の悪循環。
- 同種の修正（CI・Haversine・#63）が**別セッションで重複実装**される。

**対策案**: (a) 週1のマージデーを設定、(b) マージ後は関連ドラフトを即クローズ/リベース、(c) 夜間エージェントに「着手前に既存オープンPRの重複チェック」を課す。
