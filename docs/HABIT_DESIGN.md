# 「毎日でなくても、見たくなる」設計（2026-08-25）

**きっかけ**: 「どれだけサービスが人の習慣に入り込んでいるかが重要」
「毎日までは不要でも、見たくなるような設計が必要」（2026-08-25）

---

## 1. いま何回開く理由があるか（実測）

ペルソナに1年分のデータを入れて数えた。

```
 整備記録        733件 / 12ヶ月 / 10人   → 1人あたり 年73件（法人フリート込み）
 ドライブログ    192件 / 12ヶ月 / 10人   → 1人あたり 年19件
 車検            2年に1回（貨物は毎年）
 給油記録        機能が無い
```

個人ユーザーに絞ると、**アプリを開く理由は年に数回しかない。**

| きっかけ | 頻度 | いまアプリにあるか |
|---|---|---|
| 給油 | **月2〜4回** | **無い** |
| 洗車 | 月1〜2回 | 無い |
| 整備・点検 | 年2〜4回 | ある（記録） |
| タイヤ交換 | 年2回（降雪地） | 記録の一種として |
| 保険更新 | 年1回 | ある（期限） |
| 車検 | **2年に1回** | ある（中心機能） |

**中心機能が2年に1回しか発火しない。** これが構造上の問題。

---

## 2. 何が足りないのか

### 足りないもの その1 — 一番多い接点を取っていない

**給油は月2〜4回ある。** クルマに関わる行為で圧倒的に頻度が高い。
いま TrustCar には給油記録が無く、燃費は `drive_log` の任意フィールドに
`fuelEfficiency` があるだけ。**自分で計算して入れる人はいない。**

給油記録は、習慣化の教科書どおりの形をしている。

```
 きっかけ  給油した（外から来る。アプリが作らなくていい）
 行動      金額とリットルを入れる（20秒で終わる）
 報酬      今回の燃費が出る（毎回違う ＝ 変動報酬）
 投資      記録が溜まり、燃費の推移が伸びる
```

**「毎回違う数字が出る」のが効く。** 整備記録は入れても「記録が増えた」だけで、
返ってくるものが無い。燃費は良かった/悪かったが毎回出る。

### 足りないもの その2 — 溜めた分が返ってこない

1年で整備記録が73件溜まる。だが、それを見返す画面は**履歴の一覧**と
**メンテナンス統計**しかなく、どちらも**自分から開かないと見えない。**

溜めることには協力してもらっているのに、溜まった価値を突き返していない。
これでは「入れる意味あるのか」と思われる。

### 足りないもの その3 — 通知が「催促」しかない

いまの通知は車検・保険・オイル交換の**期限リマインド**、つまり全部
「まだやってないですよ」という催促。**催促は開く理由になるが、開きたい理由にはならない。**

催促だけのアプリは、用が済んだら消される。

---

## 3. 設計方針

> **毎日開かせない。年に十数回、開きたくなる瞬間を作る。**

クルマは毎日考える対象ではない。無理に毎日にすると通知が邪魔になって消される。
狙うのは「開く理由が年3回 → 年20回」で、そのうち何回かは**催促ではなく、
見たいから開く**状態にすること。

---

## 4. 打ち手（優先順）

### 打ち手1 — 給油記録と燃費（接点を年3回から年30回に）

**これが最優先。** 唯一、月単位の接点を作れる。

- 入力は**金額・給油量・走行距離**の3つだけ。20秒で終わること
- 保存した瞬間に**今回の燃費**を出す（変動報酬）
- 「前回より +0.8 km/L」「同じプリウスの平均より良い」を添える
- 満タン法で自動計算（走行距離は前回との差分）

**既にあるもの**: `community_maintenance_trends`（同車種の集計）。比較の相手はもういる。

**注意**: 入力が面倒だと1ヶ月で捨てられる。項目を増やさないこと。
レシート撮影でのOCR取り込みは、その次の段階。

### 打ち手2 — 「あなたのクルマの1年」（溜めた分を突き返す）

年に1〜2回、まとめて振り返るページを作って通知する。素材は**すでに全部ある**。

```
 今年の走行距離        12,400 km
 かかった費用          186,000 円（整備 92,000 / 車検 74,000 / 消耗品 20,000）
 整備した回数          6回
 いちばん高かった整備   車検（74,000円）
 同じプリウスの人の平均  費用 210,000円 ← あなたは 24,000円 安い
```

**「同車種の平均との比較」が肝。** 自分の数字だけでは良し悪しが分からない。
比べて初めて見たくなる。

年末と、登録から1年の日に出す。**催促ではない通知は、いまこれしかない。**

### 打ち手3 — 「次にお金がかかること」カレンダー

車検・保険・税金・タイヤ・オイルを1本の年表に並べ、**今後12ヶ月の出費見込み**を出す。

```
 10月  オイル交換      5,000円
 12月  タイヤ交換     40,000円
  4月  自動車税      39,500円
  6月  車検          74,000円
 ─────────────────────
 今後12ヶ月           158,500円
```

これは「見たい」というより「不安だから見る」型。だが**開く理由としては強い**し、
月々いくら積んでおけばいいかが分かる。フリート（法人）ではそのまま予算になる。

### 打ち手4 — 買い替え検討との接続

前回からの宿題。整備記録を**売るときの材料**に変える。

- 「整備履歴あり」は中古車の値段に効く。それを PDF にして出せる（Issue #64）
- 「いま売るといくら」の目安と、車検・タイヤ・保険の残り期間から
  **乗り換えるならいつが得か**を出す

1年分の記録が溜まっているからこそ出せる数字で、**溜めた意味がいちばん分かりやすい形。**

### 打ち手5 — 通知の内訳を変える

いま全部が催促。**催促以外を混ぜる。**

| 種類 | 例 | いま |
|---|---|---|
| 催促 | 車検が近い | ある |
| 報告 | 今月の燃費が出た | **無い** |
| 発見 | 同じ車種の人が、この時期にやっている整備 | **無い** |
| 振り返り | あなたのクルマの1年 | **無い** |

## 5. どの順でやるか

| # | 打ち手 | 効き方 | 大きさ | 素材 |
|---|---|---|---|---|
| 1 | 給油記録と燃費 | 接点が年3回→年30回 | 中 | 新規（モデル・画面・集計） |
| 2 | あなたのクルマの1年 | 開きたい理由を作る | **小** | **統計画面の素材が既にある** |
| 3 | 出費カレンダー | 開く理由を増やす | 中 | 期限データは全部ある |
| 4 | 買い替えとの接続 | 溜めた意味を示す | 大 | 整備記録＋残価の外部データが要る |
| 5 | 通知の内訳 | 上の1〜4に付随 | 小 | 1〜4ができてから |

**2 から始めるのが早い。** 統計画面の集計をまとめ直して1枚にするだけで、
新しいデータは要らない。テストユーザーにも見せられる。

**1 が本命。** ただし新しい入力画面を作るので、テスト配布の後になる。

## 6. 測り方

打ち手を入れたら、これを見る。入れっぱなしにしない。

| 指標 | いまの想定 | 狙い |
|---|---|---|
| 1人あたり月間の起動回数 | 0.3回（年3〜4回） | **2回以上** |
| 記録を1件以上入れた月の割合 | — | 50%以上 |
| 通知からの起動のうち、催促以外の割合 | 0% | 30%以上 |
| 登録から3ヶ月後も記録を入れている人の割合 | — | 40%以上 |

**いまは何も測っていない。** `firebase_analytics` は入っているので、
まずイベントを仕込むところから。

---

## 7. やらないこと

- **毎日開かせようとする**。クルマは毎日考える対象ではない。無理に日次にすると
  通知が邪魔になり、通知ごと切られる（そうなると催促も届かなくなる）
- **バッジやポイントで釣る**。整備は義務であって遊びではない。
  「オイル交換して10ポイント」は、この領域では白ける
- **入力項目を増やす**。給油記録が3項目を超えたら続かない
