## CI 側の決定（別PR #109 で実施済み）

**結論: ワークフロー停止ではなく恒久修正**。ただしノイズ源は遮断する。

| 事象 | 実態 | 対応 |
|------|------|------|
| `pm_report.yml` が毎回失敗 | 2026-06-15 の初回から **8/8 全失敗**。`grep -c` の exit 1 で `$GITHUB_OUTPUT` が壊れる／**テストが全緑だと落ちる**バグ | 全ステップを `set +e` ＋明示的終了コード判定に。品質結果は「報告」でありワークフローを失敗させない |
| 毎日のCI失敗通知 | `ci.yml` が `claude/**` push を対象にし、**65本**の滞留ブランチが push の度にフルCI（macos-15 の iOS ビルド含む）を起動 | push トリガーを `main` のみに限定。**PRイベントでのゲートは維持** |
| Actions ストレージ超過 | 全ブランチで APK / iOS 成果物を7日保持 | アップロードを main 限定・retention 3日に短縮。`concurrency` で重複run停止 |

> **main 自体は 2026-03 以降ずっと緑**（直近30run: 21成功 / 9失敗、失敗は全て2〜3月）。
> 赤かったのは滞留ブランチであって main ではない。

## 滞留ブランチ棚卸し（2026-08-05 実測）

`origin/claude/*` は **66本**（オープンPR保持 9本 / それ以外 57本）。

| 分類 | 本数 |
|------|------|
| main にマージ済み（＝ブランチを消しても差分が失われない） | **0本** |
| 未マージ（クローズ済みPRの差分を保持） | 57本 |
| オープンPRが参照中 | 9本 |

**マージ済みが0本なのは squash merge を使っているため**です。main のコミットは
`feat: ... (#74)` のように潰されており、元ブランチは main の祖先になりません。
そのため `git branch -d` の安全判定は全ブランチを拒否し、削除するなら `-D`（強制）になります。

> ⚠️ **訂正**: 「ブランチ整理で Actions ストレージを回収する」という説明は機構として誤りでした。
> ブランチ（ref）はストレージをほぼ消費しません。**Actions ストレージを占めているのはアーティファクト**です。

### 実際のストレージ消費

main の1 run あたりの実測:

| アーティファクト | サイズ |
|------------------|--------|
| `android-apk-debug` | 109.7 MB |
| `ios-build-debug` | 85.3 MB |
| **合計** | **約 195 MB / run** |

これが従来 **`claude/**` への push 毎**にも生成され、7日間保持されていた（CI run 総数 742）。
**PR #109 で「main 限定 ＋ retention 3日」に変更済み**のため、今後の生成は止まります。
既存分は 7日で自動失効するため（最新分の期限は 2026-08-11）、追加操作なしで自然に解放されます。

### ブランチ削除の判断

- 30本のクローズ済みPRには「**ブランチは削除しません**」とコメント済みで、再オープンでの復帰を約束している
- 削除しても Actions ストレージは減らない
- したがって **削除は見送り**、棚卸し記録のみ残す（必要になった時点でオーナー判断）
