## 2. 境界は2つあります（ここが設計の骨格）

リポジトリの文書は、この2つを区別せずに「無料/有料」と呼んでいます。
分けないと設計できません。

```
 境界A  記事と記事のあいだ
        無料記事（独立した1本）→ 3〜7日 → 有料記事（独立した1本）
        目的：人を集める。note のタイムライン・検索に面積を作る

 境界B  1本の有料記事の中
        無料エリア → 〔ここから先は有料エリア〕 → 有料エリア
        目的：買う判断をさせる。価格の正当化
```

現状の運用は、こうなっています。

```
 記事                    境界A          境界B
 ─────────────────────  ────────────  ──────────
 公開済み4本             なし           1〜23%（うち3本は未設計）
 未公開3本               あり（設計済）  36〜45%
```

**新しい3本では境界Aが導入され、境界Bも30〜45%に引き上げられています。**
方針転換は既に効いています。本書はそれを規約として固定するものです。

## 3. 境界B の設計規約（1本の記事の中）

### 規約B-1 — 無料部分は「完結した1単位」で切る

分量ではなく**単位**で切ります。`02_pricing.md:56` の原則をそのまま採ります。

> 「無料部分だけで使える」と感じた読者は、有料部分の価値を高く見積もります。

```
 良い切り方   12枚のシートのうち、シート①を丸ごと（使える）
              5つの表のうち、1つ目の表を丸ごと（使える）
              4回の研修のうち、第1回の設計を丸ごと（使える）

 悪い切り方   「まず結論から書きます」の直後で切る（使えない）
              章の途中で切る（使えない）
              目次を見せて切る（使えない）
```

**判定基準はひとつです。「無料部分だけで、読者は明日ひとつ実行できるか」。**
できないなら、それは試し読みであって無料部分ではありません。

### 規約B-2 — 無料率は 30〜45% を目安にする

未公開3本が既にこの帯（36% / 42% / 45%）に入っており、実質の社内標準になっています。

```
 〜10%   ✕  価格の正当化ができない。現在の公開済み3本がここ
 30〜45% ○  推奨帯
 50%〜   △  有料部分が「おまけ」に見える。ただし B-1 を満たすなら許容
```

**ただし率は結果です。** B-1 で単位を決めた結果として30〜45%に収まるのが正しく、
率に合わせて章の途中で切るのは B-1 違反です。

### 規約B-3 — 長い記事ほど、無料部分は「量」でなく「完了体験」で見せる

`selling_strategy.md` の診断③をそのまま適用します。

> 34,000字は、買う前の読者にとっては**重さ**でしかありません。

```
 32,919字の記事で 40% を無料にすると、無料部分だけで 13,000字。
 これは「試し読み」ではなく、それ自体が長すぎる記事になります。
```

**したがって 20,000字を超える記事では、率の上限を 25% 程度に抑え、
そのぶん B-1（完結した1単位）を厳格に守ります。**

```
 本文字数        無料率の目安    切り方
 ────────────   ────────────   ──────────────────────────────
 〜15,000字      35〜45%        完結した1単位
 15,000〜25,000  25〜35%        完結した1単位（最小のもの）
 25,000字〜      15〜25%        完結した1単位＋「残りの一覧」を見せる
```

### 規約B-4 — 目印の移動を手順に入れる

現在の不具合の直接原因です。`shared/new_article_checklist.md` と
各記事の `00_PASTE_TO_NOTE.md` 冒頭手順に、次を追加します。

```
 □ 「＝＝＝ ここに有料ラインを設定 ＝＝＝」を、この記事の切れ目まで移動した
 □ 移動後の無料率が規約B-2/B-3 の帯に入っている
 □ 無料部分だけを読んで「明日ひとつ実行できる」ことを確認した
```

`shared/build_paste.py` に、無料率を計算して逸脱時に警告を出す処理を足すのが
確実です（本書では実装していません）。

## 4. 境界A の設計規約（記事と記事のあいだ）

未公開3本で既に採用されている形を、そのまま規約にします。

```
 1. 無料記事を公開                      約2,600〜3,000字
        ↓ 3〜7日おく
 2. 有料記事を公開                      本文＋境界B
        ↓
 3. 無料記事の末尾に、有料記事のURLを差し込む
```

### 規約A-1 — 無料記事は短くする（2,600字前後）

`ai-and-my-words` の無料記事が「あえて短くしてあります」と明記しており、
これを標準とします。**無料記事は読み切らせることが役割**で、
情報量は役割ではありません。

### 規約A-2 — 無料記事と有料記事は「同じ話の前半と後半」にしない

無料記事が有料記事の要約になると、読者は有料記事を読む理由を失います。

```
 ○  無料記事：何が起きたか（現象・違和感）
     有料記事：どう回すか（手順・型・テンプレート）

 ✕  無料記事：手順の1〜3
     有料記事：手順の4〜12
```

`ai-and-my-words` はこの形になっています
（無料＝「何が消えたのかを言葉にしてみた」／有料＝「実際に回すための中身」）。

### 規約A-3 — 順番を守る

リポジトリ側の指示をそのまま引き継ぎます。

```
 shared/why_22_views.md → 1. 無料記事を、週1本で6週間出す ← いまここ
                          2. それから、有料記事を出す
                          3. 読まれてから、中身を直す
```

**境界設計は、この「2」以降に効く打ち手です。**

## 5. 公開済み4本をどうするか

### 取り下げない（リポジトリの方針を支持します）

```
 README.md「4本を、取り下げないでください」
 02_pricing.md:128-130「note の有料記事は、公開直後より積み上げで伸びます。
                        検索流入と回遊が効くのは3ヶ月目以降。
                        だから初速が鈍くても、取り下げないでください」
```

### ただし、有料ラインの位置は直せます

**取り下げずに、公開済み記事の有料ラインだけを後から動かせます**
（note の編集で「ここから先は有料エリア」の位置を変更）。

```
 記事                     現在   推奨    作業
 ──────────────────────  ─────  ─────  ──────────────────────────────
 bpr-12sheets              1%    20%    シート①を丸ごと無料側へ
                                        （02_pricing.md の当初設計どおり）
 logical-thinking-4days    1%    20%    第1回の設計を丸ごと無料側へ
 furikaeri-training        2%    25%    冒頭の1単位を無料側へ
 ai-training-materials    23%     ―     規約B-3 の帯に入っている。変更不要
```

**購入者への不利益はありません**（既に買った人は全文を読めます）。

> ⚠️ ただし §0-3 のとおり、**これで売上が動く見込みは薄いです。**
> 22ビューという分母が変わらない限り、境界をどう引いても結果は同じです。
> **この作業の意味は「読まれる状態になったときに取りこぼさない」ことです。**
> 優先度は、無料記事6本の公開より下に置いてください。

## 6. 見つかった不整合（報告）

### ① 公開本数が資料内で食い違っています

```
 README.md の記事一覧表    「公開済・動かず」が 4 本
 README.md の数字ブロック   「公開済み 2本 / 累計ビュー 22 / 販売 0部」
 selling_strategy.md       「有料記事を4本、続けて公開」
```

**4本なのか2本なのかが確定しません。**
これは診断に効きます。22ビューが4本の合計なら1本あたり5.5ビュー、
2本の合計なら11ビューで、どちらも「読まれていない」結論は変わりませんが、
**残り2本が本当に公開されているかは確認が要ります。**

### ② `02_pricing.md` が3本に無い

```
 02_pricing.md あり   bpr-12sheets / furikaeri-training /
                      logical-thinking-4days / ai-training-materials / five-tables
 02_pricing.md なし   ai-and-my-words / ai-not-used
```

`ai-and-my-words` は「次に出す1本」かつ価格が決まっている（580円→780円）のに、
価格設計の記録がありません。README には書かれていますが、
**他記事と同じ形に揃っていません。**

## 8. 調査の限界（明示）

- **note 上の実物を見ていません。** 本書の無料率は、リポジトリ内の原稿
  （`00_PASTE_TO_NOTE.md`）に置かれた目印の位置から算出したものです。

- **ビュー数・販売数は README 記載の値**（22ビュー / 0部）をそのまま使いました。
  note のダッシュボードで実測したものではありません。
- **公開本数が4本か2本か確定していません**（§6-①）。
- 字数は文字数カウント（`wc -m` 相当）で、note の表示上の字数とは一致しません。
