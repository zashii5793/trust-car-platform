## 1. 本番用Embedding切替（ROADMAP Task 1.1）

### 現状 — 実装済み。ただし本番デフォルトは TF-IDF

ROADMAP は現状を「HashEmbedding（ランダムに近い精度）」と書いているが、**この記述は既に古い**。実測した現状は以下。

| 事実 | 根拠 |
|---|---|
| バックエンドは2系統が実装済み（TF-IDF / sentence-transformers 系） | `app/rag.py:136` `_TfidfBackend`、同 `:167` 以降のモデルバックエンド |
| 切替は環境変数 `EMBEDDING_BACKEND` | `app/rag.py:9`、`app/config.py:47` |
| **デフォルト値は `"tfidf"`** | `app/config.py:47` `embedding_backend: str = "tfidf"` |
| 埋め込みキャッシュ実装済み（`chunk_id` + `text_hash` で差分再計算） | `app/rag.py:181-239`、`app/config.py:49` `embedding_cache_path` |
| モデル初期化に失敗したら TF-IDF に自動フォールバック | `app/rag.py:260-270` |
| 依存は**任意依存**（本体に入っていない） | `pyproject.toml` `[project.optional-dependencies] embedding = ["sentence-transformers>=3.0", "torch>=2.0"]` |
| テストは存在 | `tests/test_embedding.py` |

### 現行精度のベースライン（TF-IDF 実測）

`docs/benchmark_search_results.txt`（10文書 / 17チャンク）:

| 指標 | 値 |
|---|---|
| 関連質問 | 24件 |
| 回答できた | 18件（75%） |
| top1文書が正解 | **17件（71%）** |
| NO_ANSWER 誤発動 | **6件** |
| ノイズ抑制（無関係質問の棄却） | 3件中3件成功 |

**注目すべきは誤りの中身**。「車検の流れ」「計画年休とは」「廃番品の処分方法」など、**文書自体は正しく引けているのに確信度が閾値に届かず NO_ANSWER になっている**ケースが6件。これは語彙一致に頼る TF-IDF の弱点そのもので、意味ベースの Embedding が最も効く領域。逆に言えば、**切替の効果はこの6件が回収できるかで測れる**。

### 記録漏れの具体箇所（B2B監査で問われる順）

1. **`GET /api/originals/{filename:path}`（`app/main.py:3931`）— 原本ファイルのダウンロード。** 「誰がどの社内文書を持ち出したか」がまさに監査対象なのに記録されていない。**最優先。**
2. `GET /api/chunks`（`:3892`）— チャンク本文の閲覧。
3. `GET /api/admin/documents`（`:3666`）/ `GET /api/admin/queries`（`:3362`）/ `GET /api/admin/dashboard`（`:3433`）— 管理者による他人の質問履歴の閲覧。
4. `GET /api/knowledge-base`（`:3956`）。

### リスク・確認事項

- 1.3-c（テナント項目）は、**マルチテナント化するのか単一テナント配布を続けるのかの方針次第で不要になる**。現状は顧客ごとに独立インスタンスを配る形（`tenants/a_company` 1件）に見えるため、先に方針確認が要る。→ §4 の確認事項へ。
